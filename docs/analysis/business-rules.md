# 业务规则与边界

## 产品硬规则

1. 预约目标日固定为后天：`today + BOOKING_DAY_OFFSET`，`BOOKING_DAY_OFFSET=2`。
2. 系统调度固定每天 `20:00:00` 执行，创建有效方案后静默确保该任务存在。
3. 签到窗口由服务端字段判定：`begin - limitSignAgo <= nowTime <= begin + limitSignBack`。
4. 自动签到必须同意当前版本协议。
5. 启用自动签到先持久化配置，再同步系统任务；任一步失败必须回滚开关。

## 抢座执行边界

| 参数 | 默认值 | 边界 |
|---|---|---|
| `max_trials` | 5 | 必须 >= 1 |
| `retry_delay` | 1.0 秒 | 必须 >= 0，指数退避 `delay * 2^(attempt-1)` 再随机化；单次等待下限 0.1 秒 |
| `window_wait_seconds` | 30.0 秒 | 必须 >= 0；整个任务共享一个截止时间 |
| `window_poll_interval` | 1.0 秒 | 必须 > 0；运行期下限 1.1 秒（服务端约 1 秒内禁止第二次 bookSeats POST） |
| `check_in_retry_interval` | 120.0 秒 | 必须 > 0，运行时下限 10 秒 |

执行顺序：

1. 只执行已配置进调度（启用）的方案；未配置进调度的方案仅作为用户留存的备用方案，不参与执行。
2. 启用方案按智能优先级排序后依次执行：
   - 第一优先级：预约时段命中 15:00–17:00 的方案；
   - 第二优先级：预约时段命中 09:00–11:00 的方案；
   - 其余方案按默认顺序排在最后。
   同一优先级内保持默认顺序（配置中的方案顺序）；“命中”指方案时段 `[start_hour, start_hour + duration_hours)` 与目标区间有重叠；同时命中多个区间时按更高优先级处理。
3. 每个方案按主座位、备用座位顺序处理。
4. 每个座位最多 `max_trials` 次；窗口未开放期间的轮询不消耗尝试次数。
5. 成功返回后立即停止整个任务。
6. `time_out_of_range` 表示窗口未开放，按 `window_poll_interval` 轮询重试；整个任务共享一个 `window_wait_seconds` 截止时间，截止前不切换座位。
7. 未知错误采用 fail-closed 策略：只有 `CODE=ok` 才算成功。
8. 备用座位切换只在仍有候选座位时发生，且只在窗口已开放、当前座位确实不可用时发生。

服务端响应决策：

| 响应 | 决策 | 说明 |
|---|---|---|
| `time_out_of_range`（窗口未开放） | 继续轮询 | 不消耗 `max_trials`，受共享窗口截止时间限制 |
| 限流（`CODE=1`，`MESSAGE` 含“请求太频繁”） | 退避后重试 | 下次请求间隔至少 1.1 秒 |
| 已有预约（duplicate） | 跳过当前座位 | 无需重复预约 |
| 座位不可用（seat_unavailable） | 跳过当前座位 | 换下一个候选座位 |
| 非法请求 / 请检查参数设置 / 过去时间 | 停止任务或跳过 | 永久性错误，不重试 |
| 未知错误 | 退避重试，最多 2 次 | 仍失败则跳过当前座位，不视为成功 |

## 结果判定

- 预约接口成功响应不直接视为成功。
- 必须通过 `myBookingList?fromType=web` 复核 `seatNum + time(±1s) + duration` 三者匹配。
- 超时后也要做同样复核，防止“服务端已写入但响应超时”。
- `CODE=ok` 但复核未命中时，先延迟 1~2 秒重新复核一次；仍不命中按“不确定”处理，不得立即重发同一座位（避免重复预约），并停止该座位的后续尝试。
- 复核查询是 best-effort：结构漂移返回 `[]`，不升级为硬错误。

## 预约操作门禁

| 操作 | 允许状态 | 成功后状态 |
|---|---|---|
| 取消 | `0` / `8` | `4` 或记录消失 |
| 签到 | `0` 且进入签到窗口 | `1` |
| 暂离 | `1` | `2` |
| 返回座位 | `2` | `1` |
| 续座 | `2` | `1` |
| 签退 | `1` | `3` / `7` |

说明：

- `6`（暂离未归）不允许恢复。
- 操作成功后必须从预约列表复核最终状态。
- 取消允许“记录消失”视为成功；其他操作不允许。

## 调度策略边界

- 策略文件缺失时使用“每天、启用”的兼容默认值。
- 策略文件损坏时安全暂停，不按默认规则执行。
- `next_booking_date()` 从 `today + 2` 开始查找，最多 90 天。

## 配置边界

- `STUDENT_ID` 与 `PASSWORD` 必须成对出现，禁止与对应 `_FILE` 同时设置。
- 所有可写路径必须是绝对路径。

## 安全边界

- 未认证状态禁止任何业务查询、方案操作、抢座、签到和调度管理。
- 远端明确返回 `is_login=false` 时立即清除本地认证状态并发布 `AUTH_REQUIRED`。
- 生产构建（Ktor）不注册文档路由：`/api/docs` 与 `/api/openapi.json` 返回 `404`。
- `/api/v1/status` 不暴露密码或凭证。
- 审计日志不写 Cookie、密码或请求签名。
